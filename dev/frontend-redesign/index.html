    1. 设计理念与设计系统¶

    1.1 产品定位¶

    Datus 不是一个普通的聊天机器人,而是一个数据智能工作台 (Data Workbench)。用户来这里的目的是:

    • 用自然语言与数据对话
    • 让 Agent 辅助完成数据分析、数据库查询、数据采集等任务
    • 获得可信任的、可追溯的分析结果

    核心设计原则: 精密、可信、透明

    1.2 设计语言: 精密仪器¶

    从三个参考意象中提取设计语言:

    意象 提取的设计元素
    金融数据终端 (Bloomberg Terminal) 深色画布、高信息密度、精确的排版、色彩只用于数据本身
    IDE 工作台 (VS Code / JetBrains) 可折叠面板、上下文感知的状态栏、命令面板、键盘优先
    实验室控制台 状态指示灯、进度追踪、可暂停/干预的工作流

    1.3 设计 Token 系统¶

    色板¶

    /* 主画布 — 深色,减少视觉疲劳,让数据发光 */
--bg-canvas:       #0f172a;   /* 主背景,深海军蓝 */
--bg-surface:      #1e293b;   /* 面板/卡片表面 */
--bg-elevated:     #334155;   /* 悬浮/模态/下拉层 */
--bg-hover:        rgba(255, 255, 255, 0.05);

/* 主色 — 青金石蓝,代表数据与智能的融合 */
--accent:          #06b6d4;   /* 主色调 */
--accent-soft:     rgba(6, 182, 212, 0.12);
--accent-glow:     rgba(6, 182, 212, 0.25);

/* 语义色 — 只用关键信息 */
--amber:           #f59e0b;   /* 数据高亮/指标标记 */
--emerald:         #10b981;   /* 成功/完成 */
--danger:          #ef4444;   /* 错误/中断 */
--info:            #3b82f6;   /* 信息/提示 */

/* 文字 — 高对比度,保证可读性 */
--text-primary:    #f1f5f9;
--text-secondary:  #94a3b8;
--text-muted:      #64748b;

/* 边框 */
--border:          rgba(148, 163, 184, 0.12);
--border-hover:    rgba(148, 163, 184, 0.25);

    字体¶

    角色 字体 权重 说明
    UI / 正文 Inter 400 / 500 / 600 / 700 数据密集型 UI 首选,精密克制
    数据 / 代码 JetBrains Mono 400 / 500 / 600 等宽,适合 SQL、代码、指标
    展示标题 Plus Jakarta Sans 600 / 700 / 800 几何感,用于大标题和品牌文字

    注意: Plus Jakarta Sans 需要 npm 安装 (@fontsource/plus-jakarta-sans),也可以回退到 Inter 的 display 权重。

    间距与圆角¶

    沿用 4→8→16→24→32→48 体系,但调整圆角:

    层级 圆角 适用
    最小元素 4px 标签、徽章、小图标
    卡片/面板 8px 卡片、侧边栏、面板
    输入框/模态 12px 输入框、对话框、大容器
    按钮 6px 所有按钮
    圆形 9999px 头像、状态点

    阴影¶

    --shadow-sm:   0 1px 3px rgba(0,0,0,0.3);
--shadow-md:   0 4px 12px rgba(0,0,0,0.35);
--shadow-lg:   0 8px 30px rgba(0,0,0,0.4);
--shadow-accent: 0 0 0 3px var(--accent-glow);

    1.4 图标系统¶

    现状: 导航和任务类型使用 emoji 图标 (🏠 ✚ 🔍 📜 等)

    改进: 使用 SVG 线框图标集 (推荐 Lucide 或 Heroicons)

    • 统一 20px 视口 (导航) / 24px (卡片)
    • 描边宽度 1.5px
    • 颜色继承 currentColor
    • 交互状态: hover 时描边加粗或填充

    导航图标映射:

    页面 当前 emoji 替换图标 (Lucide)
    首页 🏠 LayoutDashboard
    新建任务 ✚ Plus
    数据探索 🔍 Search
    会话历史 📜 History
    数据源 🔌 Cable
    技能市场 🛍️ Puzzle
    知识库 📚 Library
    设置 ⚙️ Settings

    2. 页面级重构方案¶

    2.1 整体布局¶

│ ┌──────────┐  ┌──────────────────────────────────────┐  │
│ │          │  │                                      │  │
│ │ Sidebar  │  │          Main Content Area           │  │
│ │ (折叠式)  │  │                                      │  │

    现状问题: - emoji 图标不够精致 - 会话列表和导航混在一起 - 缺少搜索和固定功能

    重构方案:

    ┌──────────────────┐
│  ◆  Datus        │  ← 品牌 Logo + 名称
│                  │
│  ◇ 首页          │  ← SVG 线框图标
│  ＋ 新建任务      │
│  ◇ 数据探索      │
│  ◇ 会话历史      │
│ ───────────────── │
│  ◇ 数据源        │
│  ◇ 技能市场      │
│  ◇ 知识库        │
│  ◇ 设置          │
│ ───────────────── │
│  最近会话         │
│  [搜索会话...]    │  ← 新增搜索
│  ○ 销售分析...    │
│  ○ 用户留存...    │
│  ○ GMV 归因...    │
│ ───────────────── │
│  ◎ User        ⚙️ │  ← 用户+设置
└──────────────────┘

    具体规范: - 导航项高度: 36px, 间距 2px - 激活态: 左侧 2px 青色竖条 + 浅青背景 - 会话列表: 最多显示 10 条,支持搜索过滤 - 折叠态: 只显示图标, hover 展开 tooltip 显示名称 - "新建对话"按钮改为侧边栏顶部的 ＋ 图标按钮

    2.3 首页 (Dashboard)¶

    现状问题: - 6 张 emoji 卡片平铺,看起来像通用后台模板 - 系统状态和功能入口混在一起 - 缺少"智能感"

    重构方案:

    ┌──────────────────────────────────────────────────────┐

│ ┌────────────┐ ┌────────────┐ ┌────────────┐        │
│ │ ▓ 数据源    │ │ ▓ Agent    │ │ ▓ 知识库    │        │
│ │ 3 个已连接  │ │ 2 个可用   │ │ 已构建      │        │
│ │ 最后同步:.. │ │ 数据分析师  │ │ 12 个主题   │        │
│ └────────────┘ └────────────┘ └────────────┘        │
├──────────────────────────────────────────────────────┤
│ 快速开始                                             │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐              │
│ │ 对话查询  │ │ 数据库问数│ │ 数据采集  │              │
│ │ 自然语言  │ │ 选表查数  │ │ URL 采集  │              │
│ │ 分析数据  │ │ 生成报告  │ │ 结构化   │              │
│ └──────────┘ └──────────┘ └──────────┘              │
├──────────────────────────────────────────────────────┤
│ 试试这样问                                           │
│ [统计近30天各品类销售额] [找出客户流失原因]            │

└──────────────────────────────────────────────────────┘

    具体规范: - 顶部状态卡片: 3 个大卡片,显示关键系统状态,点击跳转到对应配置页 - 快速开始: 3 个核心场景,替代原来的 6 个功能入口 - 示例 prompt: 标签样式,点击直接跳转到聊天页并填充对应任务类型 - 去掉"技能市场"和"会话历史"的首页入口 (它们属于侧边栏导航) - 整体信息密度降低,但数据密度提高

    2.4 聊天页 (ChatPage) — 核心页面¶

    这是重构的重点,分三个状态描述

    状态 A: 初始状态 (无消息)¶

    现状问题: TaskPanel + BuiltInSkillsPanel + ChatArea 三个面板同时出现,信息过载

    重构方案:

    ┌──────────────────────────────────────────────────────┐

├──────────────────────────────────────────────────────┤
│                                                      │
│                    你想分析什么?                      │
│           上传表格或关联数据源,我来做清洗、           │
│           建模、可视化,并写出结论。                   │
│                                                      │
│  ┌──────────────────────────────────────────────┐   │
│  │ 分析 2025 年中国新能源汽车销量数据...  [↑]    │   │
│  └──────────────────────────────────────────────┘   │
│   📎 上传文件      📋 分析深度: 标准 ▼  输出格式 ▼  │
│                                                      │
│  快速开始                                            │
│  ┌──────────────────┐ ┌──────────────────┐          │
│  │ 销售趋势与同环比  │ │ 客户分群与复购   │          │
│  │ 6 张图表          │ │ 建模             │          │
│  └──────────────────┘ └──────────────────┘          │
│                                                      │
└──────────────────────────────────────────────────────┘

    关键变化: - 任务类型选择从左侧面板改为顶部的频道标签 (3 个标签切换) - 输入框居中,视觉重心突出 - 文件上传、输出选项折叠在输入框下方一行 - 快速操作卡片减少到 2 个,更聚焦

    • 工具调用显示为可折叠卡片,包含调用参数和返回摘要
    • 流式文本显示打字机效果 + 光标闪烁

    2.6 知识库页 (KnowledgeBasePage)¶

    现状问题: 主题卡片信息少,搜索体验平淡

    重构方案: - 主题卡片增加: 文档数量、最后更新时间、构建状态 - 搜索高亮关键词 - 构建流程: 选择数据源 → 选择文档 → 确认 → 进度条 → 完成 - 增加"引用此知识库"开关,在聊天上下文中显示

    2.7 技能市场页 (SkillShopPage)¶

    现状问题: 布局可优化,搜索和筛选可增强

    重构方案: - 三列等宽卡片网格 - 卡片包含: 图标、名称、描述、标签、版本、安装状态、操作按钮 - 详情面板: 点击卡片后右侧滑入,不覆盖列表 - 搜索 + 分类筛选 (内置/已安装/全部)

    3. 交互模式与组件规范¶

    3.1 Agent 思考过程组件 (ThinkingProcess)¶

    这是本次重构最重要的新组件

    Props:
- steps: AgentStep[]  (id, label, status, detail?, duration?)
- currentStep: string | null
- onToggleExpand: (stepId) => void
- onPause: () => void
- onResume: () => void
- onStop: () => void
- collapsed: boolean   (默认展开最后一步,其余折叠)

状态机:
  pending → processing → completed
                       → failed
                       → paused (仅当前步骤)

视觉:
- 垂直时间线布局
- 每个步骤左侧有状态点 (灰色/青色脉冲/绿色/红色)
- 步骤间用细线连接
- 当前步骤: 高亮 + 脉冲动画
- 已完成步骤: 可点击展开查看详情
- 工具调用步骤: 显示为代码块样式卡片

    3.2 上下文条 (ContextBar)¶

    Props:
- agent: { id, name, icon } | null
- datasource: { name, type } | null
- model: { id, name, provider } | null
- planMode: boolean
- onAgentChange, onDatasourceChange, onModelChange, onPlanModeToggle

视觉:
- 单行,标签样式 (pill/badge)
- 每个标签: 图标 + 名称 + 下拉箭头
- 点击弹出选择器浮层 (而非下拉框)
- 规划模式: 独立的切换按钮,带状态指示
- 背景: 半透明,融入消息区域顶部

    3.3 消息气泡增强 (MessageBubble)¶

    现状: 简单的用户/助理气泡,无操作

    改进: - 用户消息: hover 出现编辑按钮,点击进入编辑模式 - 助理消息: - 消息头部: Agent 头像 + 名称 + 模型名 + 耗时 - 思考过程: 嵌入 ThinkingProcess 组件 - 结果正文: Markdown 渲染增强 - 消息底部: 操作按钮组 (复制/重新生成/继续追问) - 流式消息: 显示打字机光标 + 思考过程实时更新

    3.4 输入框增强 (InputBox)¶

    现状: 纯文本输入 + 发送按钮 + 工具栏

    改进: - 输入框: 自动调整高度,支持 / 命令触发技能自动补全 - 左侧 + 按钮: 展开菜单 (上传文件、选择技能、引用知识库) - 输入框下方: 上下文摘要条 ("正在使用 sales_db · 数据分析师 · GPT-4o") - 底部: 字数统计 + 快捷键提示 (Enter 发送, Shift+Enter 换行) - 发送按钮: 流式时显示为暂停图标,可点击暂停

    3.5 暂停-反馈-继续机制¶

    新增交互模式,对应参考文章中的模式 6:

    触发时机:
1. 用户手动点击暂停按钮
2. Agent 到达关键决策点 (如: 需要确认 API 调用参数)
3. Agent 检测到需要用户输入

暂停状态:
- 暂停按钮变为继续按钮
- 显示"已暂停"指示器
- 提供选项: 继续 / 修改输入 / 中止并保存
- 修改输入: 打开编辑面板,用户可调整指令后继续

视觉:
- 暂停: 两个竖线图标 ⏸
- 继续: 三角形图标 ▶
- 暂停状态: 消息区域顶部显示黄色横幅

    3.6 快捷键系统¶

    快捷键 动作
    Enter 发送消息
    Shift+Enter 换行
    ⌘/Ctrl+K 打开命令面板
    ⌘/Ctrl+N 新建对话
    ⌘/Ctrl+, 打开设置
    ⌘/Ctrl+Shift+P 切换规划模式
    Esc 关闭浮层/模态
    ↑ 在输入框编辑上一条消息
    / 触发技能自动补全

    3.7 响应式断点¶

    断点 布局变化
    ≥ 1024px 完整三栏布局
    768-1023px 侧边栏自动折叠,上下文条缩短
    < 768px 侧边栏收起为抽屉,上下文条隐藏为图标,输入框全宽
